## Targets and what the plans reach

- **Peak under 80 MB.** Plan 007 removes the 867 MB peak and the 150 to 270 MB that stays after it from the app process. Plans 009, 010, and 011 remove the next three sources. The helper process of plan 007 still needs about 800 MB for about 50 seconds.
- **Idle under 20 MB.** Not reachable with the current UI stack. About 9 MB is system framework data, 12.5 MB is Metal drawables while the window draws, 8.7 MB is CoreAnimation and AppKit, and about 14 MB is inside the nanoui dependency. Plan 012 produces the exact figures and the reachable number.

## Findings considered and not planned

Rejected on 2026-11-26:

- **Run inline search off the UI thread.** The slowest measured query is 12.1 ms, and one-word queries are under 1 ms. A worker thread would add a stale-result state to the search machine in `src/STATE_MACHINES.md` section 10 for no visible gain. Measure again if the index grows past 10 million entries.
- **Refresh plans 002 to 006.** They had already landed. The index now says so.

Deferred. Each is real, with a larger design or a less certain gain:

- **Write the live overlay back to the index file** (open hazard H4 in `src/STATE_MACHINES.md`). Each start replays every file event since the last full build: about 40 seconds at 52% CPU for a 2-hour gap. Plan 008's log decides the order of this work.
- **Replay a gap before a full rescan** (open hazard H3). The Rust reference does it in `ref/rust/founder/crates/fsearch/src/engine.rs:720-800`. Plan 008's maintenance notes hold the decision table.
- **Lower the rescan's own memory.** `walk.RawEnt` is 40 bytes per entry, every listing stays in memory until the build ends, and the build holds a second copy. After plan 007 this memory is in the helper, not the app.
- **Draw icons and previews off the UI thread.** Each new folder path costs one `iconForFile:` call during a frame. No hitch was measured.
- **Per-entry hash lookup for overrides**, **small folder scopes**, **three-letter fuzzy words without a floor**, **cold first query**: carried over from 2026-11-24, not measured again.

Rejected on 2026-11-24:

- **Send `ext:` multi-word queries through the folder memo.** A prototype made `src main ext:zig` slower, 128 µs to 5.6 ms.
- **Fix `SearchCache` in place.** The uncached search was faster at every measured keystroke.
