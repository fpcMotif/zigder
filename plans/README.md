## Findings considered and not planned

Deferred. Each is real, with a smaller or less certain gain:

- **Per-entry hash lookup for overrides**: `Live.kindOf` and `Live.mtimeOf`
  look up `dir_overrides` for every entry. One override doubled `kind:dir`
  from 3,077 µs to 6,559 µs. A bitset in front of the map would fix it.
  `zig/live.zig` is under edit by another session.
- **Scan buffers keep their peak size**: the scan pool's per-thread hit lists
  held 9.14 MB after one broad query. Plan 004 removes the main trigger.
  Measure `after_search_mb` again before planning a trim.
- **Small folder scopes**: `in:~/devv/zigder e` still scans all names
  (5.6 ms after plan 002). The Rust code builds a name set for a small scope
  (`scope_names` in `founder/crates/fsearch/src/query.rs`).
- **Three-letter fuzzy words without a floor**: `con` 2.0 ms, `rea` 0.9 ms at
  limit 200. Plan 006 does not help them.
- **Cold first query**: 1 to 3 ms of page faults for each new first letter.
  The Rust code warms the index on a thread.
- **`ext:json` 1.8 ms, `kind:dir` 3.4 ms**: full entry scans with zone skips.
  Not a visible delay.

Already tracked in `zig/STATE_MACHINES.md` by another session, so not
planned here:

- Lost FSEvents and root rescans never rebuilt the index (D1, marked fixed).
- `Engine.mutex` is held during disk I/O (H2, open).
- The overlay is never written back to the index file (H4, open).

Rejected:

- **Send `ext:` multi-word queries through the folder memo**: a prototype
  made `src main ext:zig` slower, 128 µs to 5.6 ms. Plan 005 excludes them.
- **Fix `SearchCache` in place**: it needs the seed floor turned off to
  collect a full list, which is the cost. The uncached search is faster at
  every measured keystroke.

## Direction (options, not ranked against the plans)

- **Run inline search off the UI thread.** `updateInlineSearch` in
  `zig/app.zig` calls `Engine.runSearch` on the UI thread under the engine
  lock. After plan 005 the slowest measured query is still 36 ms, which is
  two dropped frames. A worker with a generation counter removes the stall
  for any query. Cost: results arrive one frame late and need a stale check.
- **Port the Rust scope name set.** The app's default scope can be the
  current folder. A small scope should cost time in proportion to the folder,
  not to the 663,491 unique names.
- **Set budgets on the new bench rows.** After plans 004 to 006, add budgets
  for `src main` and `nan` from three bench runs on the target machine.
